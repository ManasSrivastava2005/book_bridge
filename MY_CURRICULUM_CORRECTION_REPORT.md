# My Curriculum product correction

Implemented and activated on 4 October 2026 in `C:\Backend\bookbbbb`.

## Student workflow

1. Open **My Curriculum** and select **Add Subject**.
2. Enter a subject name, semester and optional code. No staff-created subject is required.
3. Add one or more exams, each with its own name/date. Coverage can be selected after the syllabus is confirmed.
4. Upload that subject's syllabus PDF. It remains private to the owner.
5. Review the extracted text and proposed units/topics. Rename, add or remove units/topics and edit subtopics, then choose **Confirm Curriculum**.
6. Select the units or individual topics covered by each exam.
7. Set daily study minutes. The Learning Path prioritizes incomplete topics covered by upcoming exams and schedules them within that shared daily budget.

Semester cards show real topic totals, completion percentages and upcoming exams. Subject details contain exams, PDF review, confirmed-topic progress, catalogue book matches and the Learning Path. Existing personal curricula, topic IDs and completion history remain available. Earlier unassigned uploads are listed inside subject details so students can explicitly review them into the chosen subject.

There is no fixed subject-count limit. Creation is incremental; 110 subjects in a semester passed validation and persistence testing. Semesters retain the existing 1–20 range. Changing semesters does not overwrite previous semesters.

## Limits and behavior to understand

- Schedules estimate 30 minutes per topic. Students choose 15–720 daily minutes shared across subjects; this is an estimate, not a learned measure of topic difficulty. Topics can span days. Deadlines at risk are shown.
- PDF extraction is deterministic and uses the existing local extractor. No paid API or new model was introduced. Scanned PDFs need selectable text; OCR is not included. Existing limits remain 10 MB, 100 pages and 300,000 extracted characters, with explicit errors rather than silent truncation.
- Candidate headings and short lines can need correction. Nothing extracted becomes active before confirmation. Unit/topic-per-node validation bounds remain; they do not impose a subject-count limit.
- Recommendations explain catalogue metadata matches and do not guarantee that a book covers the full syllabus.
- Older custom-subject exams remain visible as retained history. Students must choose a structured personal subject and explicit topic coverage for the new schedule.
- Legacy inactive Academic Plan source files and database tables are retained for historical recovery; no active student route invokes their task generator.
